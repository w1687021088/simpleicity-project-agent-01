# Design

## Context

首页当前为简单欢迎内容，`MainLayout` 的主内容区只承担页面渲染。当前实现使用固定高度的输入区，并要求输入扩展不影响上方区域；新的目标改为类 DeepSeek 布局，让输入区高度由内容决定，并允许上方聊天区域被压缩后通过滚动查看。相关范围见 `proposal.md`，行为约束见 `specs/home-chat-input/spec.md`。

## Goals / Non-Goals

**Goals:**

- 使用类 DeepSeek 的上下分区聊天布局。
- 输入区作为 flex 最后一个 `shrink-0` 子元素自然贴底，不使用固定高度或预留五行空间。
- 输入区高度由内容决定，单行内容只占单行高度。
- 上方聊天区域使用 `flex-1 min-h-0 overflow-y-auto`，允许被压缩并滚动。
- 发送按钮使用 `align-self: flex-end` 固定在输入区右下角。
- 输入字段最多扩展到约五行，超出后在内部滚动。

**Non-Goals:**

- 不实现消息列表数据、历史记录、会话切换或持久化。
- 不接入聊天接口、流式响应或错误重试。
- 不改变鉴权、路由或全局视觉主题。
- 不支持回车直接发送或 `Ctrl/Cmd + Enter` 快捷发送。

## Decisions

### 首页使用类 DeepSeek 的弹性上下布局

保持 `MainLayout` 主内容区为纵向 flex 容器，首页根容器使用 `flex min-h-0 flex-1 flex-col`。上方聊天区域使用 `flex-1 min-h-0 overflow-y-auto`，在输入区增高时允许被压缩，内容超出可见高度后由该区域自身滚动。

输入区作为首页 flex 布局的最后一个 `shrink-0` 子元素，不使用固定高度、不预留五行空间。由于它是最后一个 flex 子元素且上方区域占用剩余空间，输入区会自然贴在布局底部；输入区自身高度由表单和 `Textarea` 内容决定。

备选方案：为输入区设置固定最小高度。该方案会在单行输入时保留额外空白，因此不采用。

### 新增 Textarea 基础组件

在 `src/components/ui/textarea.tsx` 新增通用多行输入组件，样式保持与现有 `Input` 一致，并默认禁用拖拽缩放。首页从 `Input` 改为 `Textarea`，发送操作继续复用 `src/components/ui/button.tsx`。

多行输入组件使用单行最小高度，使用最大高度限制约五行，并启用内部滚动。输入区外层高度保持 `auto`，因此单行内容时只占单行高度，多行内容时随字段高度变化。

备选方案：直接在首页内写原生 `textarea`。该方案会重复设计系统样式，不利于后续复用，因此不采用。

### 通过受控高度同步实现自动扩展

使用 `ref` 获取输入字段元素，在内容变化时先将高度重置为 `auto`，再根据 `scrollHeight` 设置实际高度。外层输入区不设置固定高度；输入字段自身的最大高度负责限制最多约五行，超过限制后浏览器在输入字段内部显示滚动条。提交成功后清空状态，高度同步逻辑将字段恢复到单行高度。

备选方案：仅依赖 CSS `field-sizing-content`。该方案代码更少，但浏览器兼容性不如显式测量方案可控，因此不采用。

### 表单提交只由发送按钮触发

保留表单提交模型并使用 `trim()` 判断空值。回车在 `textarea` 中插入换行，不触发发送；用户点击发送按钮时提交非空内容。表单使用 `items-end` 布局，发送按钮自身使用 `align-self: flex-end` 保持在右下角。非空提交后仅触发本地处理并清空输入，不产生网络副作用。

备选方案：回车发送、`Shift + Enter` 换行。该方案不符合本次多行输入预期，因此不采用。

## Risks / Trade-offs

- [风险] 输入区增高会压缩上方聊天区域 → 缓解：上方区域使用 `min-h-0 overflow-y-auto`，内容仍可滚动查看。
- [风险] 输入区最大高度过大时占用过多空间 → 缓解：`Textarea` 保持约五行最大高度，超出后内部滚动。
- [风险] 行高与字体缩放导致五行上限不精确 → 缓解：规格使用“约五行”，实现以行高计算最大高度并允许视觉误差。
- [风险] 移动端软键盘可能遮挡底部输入区 → 缓解：使用 flex 内容流布局而非视口固定定位，浏览器可滚动适配软键盘。
- [风险] 当前“提交”没有实际消息承载 → 缓解：规格明确这是前端交互边界，后续接入消息系统时再扩展。

## Migration Plan

无需数据迁移。实现时删除输入区外层固定高度，调整首页 flex 布局和滚动区域，并保留 `Textarea` 自动扩展逻辑；回滚时恢复固定输入区布局即可。
