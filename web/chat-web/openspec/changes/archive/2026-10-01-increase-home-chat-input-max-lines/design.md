# Design

## Context

首页聊天输入框当前使用 `MAX_TEXTAREA_HEIGHT = 120` 和 `max-h-[7.75rem]`，实际效果约为 5 行后进入内部滚动。本次只调整最大展开高度，不改变现有 flex 布局、提交交互和按钮位置。

## Goals / Non-Goals

**Goals:**

- 让输入框在约 7 行以内随内容自动扩展。
- 超过约 7 行后停止增高，并在输入框内部滚动。
- 保持输入区高度仍由内容决定。

**Non-Goals:**

- 不改变上方聊天区域的可压缩与滚动行为。
- 不改变回车换行、按钮提交、空内容禁用等交互。
- 不引入新的依赖或布局结构。

## Decisions

### 同步调整最大高度常量和样式上限

将 `MAX_TEXTAREA_HEIGHT` 从 `120` 提高到可容纳约 7 行的像素高度，并同步调整 `Textarea` 的最大高度样式，例如使用 `160px` 和 `max-h-[10rem]`。这样 7 行内容不会过早进入滚动，超过 7 行后仍由现有 `scrollHeight` 逻辑触发内部滚动。

备选方案：只调整 Tailwind 类而不调整常量。该方案会导致 JS 高度计算和 CSS 最大高度不一致，因此不采用。

## Risks / Trade-offs

- [风险] 输入区增高后会进一步压缩上方聊天区域 → 缓解：现有上方区域已使用 `min-h-0 overflow-y-auto`，仍可滚动查看内容。
- [风险] 行高随字体或缩放变化导致 7 行阈值不精确 → 缓解：规格使用“约七行”，并以实际行高和浏览器测量为准。

## Migration Plan

无需数据迁移。实现时同步调整两个最大高度值，并通过手动输入 7 行和 8 行验证扩展与滚动边界。
